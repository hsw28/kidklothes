# layetteout (Expo MVP)

Cross-platform React Native app (iOS + Android) for saving kids clothing items by URL and building outfits.

## Stack

- Expo + React Native + TypeScript
- React Navigation (tabs + native stacks + deep linking)
- Local persistence with `expo-sqlite`
- Structured so storage logic can be swapped later (e.g. Supabase adapter)

## Setup

```bash
npm install
npm run start
```

Then press `i` for iOS simulator or `a` for Android emulator.

## Monetization / RevenueCat

RevenueCat is wired through the React Native app layer in `src/services/purchases.ts`.

Create a local `.env` file from `.env.example` and set:

```bash
MONETIZATION_ENABLED=true
REVENUECAT_IOS_API_KEY=your_revenuecat_ios_sdk_key
REVENUECAT_ANDROID_API_KEY=
REVENUECAT_OFFERING_ID=default
REVENUECAT_PRO_ENTITLEMENT_ID=layette_out_pro
```

Notes:

- Use a `test_...` RevenueCat key only for sandbox/testing.
- Replace the test key with your public Apple SDK key before launch.
- The expected RevenueCat setup is one entitlement (`layette_out_pro`) and one offering (`default`) with package types `monthly`, `annual`, and `lifetime`.
- Rebuild the app after changing Expo config env values so native builds pick them up.

### Android (works end-to-end)

1. Install dependencies:

```bash
npm install
```

2. Generate native project and apply config plugin:

```bash
npx expo prebuild
```

3. Run Android dev build:

```bash
npx expo run:android
```

4. In Chrome/Safari (Android), use Share on a product page and pick **layetteout**.
5. App opens to Add Item with URL prefilled.

Notes:

- Requires a dev build or production build (not Expo Go) because share intents are native.
- Android handling is configured by the `expo-share-intent` plugin in `/Users/Hannah/Programming/layetteout/app.json`.

Troubleshooting:

- This project pins Gradle to JDK 17 via:
  - `/Users/Hannah/Programming/layetteout/android/gradle.properties`
  - `org.gradle.java.home=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home`
- If Android build still fails, stop old daemons and retry:
```bash
cd /Users/Hannah/Programming/layetteout/android
./gradlew --stop
cd /Users/Hannah/Programming/layetteout
npx expo run:android
```

### iOS (best possible in Expo workflow)

Implemented with `expo-share-intent` plugin and deep-link routing, but requires native build steps:

1. Prebuild native iOS project:

```bash
npx expo prebuild
```

2. Build/run iOS dev client:

```bash
npx expo run:ios
```

3. In Xcode, ensure the Share Extension target generated by plugin is included in your signing/provisioning setup.
4. Share a URL from Safari and choose **layetteout**; shared URL should route into Add Item.

Notes:

- Expo Go does not support custom share extension targets.
- If team provisioning/capabilities block extension installation, Android flow still works and manual URL entry in Add Item remains available.

## Outbound Links

Item detail opens store links through:

- `/Users/Hannah/Programming/layetteout/src/utils/outbound.ts` (`buildOutboundUrl`)

Current behavior uses a rule-based resolver:

- tracks `sourceDomain`, `canonicalUrl`, `outboundUrl`, `clickCount` per item
- applies per-domain affiliate rewriting rules only when enabled
- keeps rules disabled by default for safe rollout

Future affiliate integration can be implemented inside that function:

- Skimlinks or Sovrn redirect/wrapper URL generation
- direct merchant URL rewriting with campaign/subid params
- per-domain attribution logic and policy checks

Disclosure support:

- Settings has a `Monetized links` toggle with disclosure text.
- Shared wishlist exports include a disclosure line when monetization is enabled.
